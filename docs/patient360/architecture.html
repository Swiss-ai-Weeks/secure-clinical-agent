Patient360 secure clinical agent — full architecture

Runtime on top, stores in the middle, offline ingestion at the bottom. The only path from the agent to any store runs through the backend's policy decision point.

The agent never touches data

The sandbox's network policy allows egress only to the backend's tool endpoints, and tools are read-only. Every call passes through the policy decision point before any store is read.

Identity is injected, never passed

The /chat endpoint mints a short-lived run token bound to the session and registers it with the OpenShell gateway. The agent only ever sees a placeholder; the gateway substitutes the real token at egress and tool endpoints verify it. No prompt, injected note, or forged header can change who is asking. One sandbox per session keeps workspaces and tokens from mixing.

Models run outside the sandbox

Inference goes to inference.local, which the OpenShell gateway proxies to a local NIM or the NVIDIA cloud endpoint. Credentials live in the gateway store, never on the agent's filesystem. Embedding and imaging models run at ingestion time or behind backend tools.

Guardrails are the second wall

Input and output rails catch injection and paraphrased leakage, but the authorization boundary is the tool layer. A fully jailbroken agent still has no path to the database.

Known residuals

Injection can steer what the caller asks for within their own scope. Inference from authorized fields, aggregate differencing, and third-party mentions inside a record are only partly mitigated by derivative-field redaction, k-minimum plus complement suppression, output rails, and ingestion scrubbing. Break-glass is a human action in the dashboard, never an agent tool.

Pseudonymous keys, isolated linkage

Records are de-identified in content but joined by an opaque patient key. The mapping to real identity lives in the linkage vault, read only by registration, break-glass, and a PDP-checked identity endpoint that renders a patient banner in the dashboard for clinicians with an active treatment linkage. The agent, tools, prompts and logs never see a name. Researchers get per-project keys and shifted dates.

Pixels bypass the agent

Only radiology reports and VLM-generated text reach the LLM. The viewer fetches DICOM directly from Orthanc with a short-lived signed URL issued by the same policy engine.
